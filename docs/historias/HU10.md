## Tarjeta

- **Como:** Administrador de cancha
- **Necesito:** poner una cancha como disponible o inactiva
- **Para:** dejar de recibir reservas en una cancha que no está en servicio

> Como Administrador de cancha, necesito poner una cancha como disponible o inactiva, para dejar de recibir reservas en una cancha que no está en servicio


## Conversación historia

- **Requisito de información:** Modelo de dominio enriquecido, hoja Cancha: atributos y responsabilidad cambiarEstado y publicarEnBusqueda (políticas 2, 7, 10, 11 y 12).
- **Prototipo:** Prototipo «Canchas del escenario»: Prototipos/Celular y Prototipos/Computador, archivo «07 Canchas del escenario.png» (1.1.9.5 Artefactos apoyo).
- **Catálogo de mensajes:** Catálogo de mensajes - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo), hoja «Mensajes». Códigos usados en esta HU: EXI-CAN-03, ERR-CAN-02, ERR-CAN-07, ERR-CAN-10, ERR-CAN-12.
- **Catálogo de parámetros:** No aplican parámetros de negocio.
- **Restricciones de diseño:** Validación de propiedad en el servidor a partir del usuario del token de acceso.
- Los estados posibles son DISPONIBLE e INACTIVA. Una cancha inactiva no aparece en la búsqueda ni admite nuevas reservas (RN-04).
- No se puede inactivar una cancha con reservas confirmadas futuras (RN-17): primero deben cumplirse o cancelarse.

## Criterios de aceptación

| Código | Escenario |
|---|---|
| CA1 | Dado que un administrador de cancha quiere sacar de servicio una cancha DISPONIBLE, cuando ejecute la acción definida para inactivarla, entonces la cancha queda en estado INACTIVA, deja de aparecer en la búsqueda y en la ficha del escenario, ya no admite nuevas reservas y se muestra el mensaje de éxito (EXI-CAN-03), indicando el nuevo estado de la cancha. |
| CA2 | Dado que un administrador de cancha quiere volver a ofrecer una cancha INACTIVA, cuando ejecute la acción definida para activarla, entonces la cancha queda en estado DISPONIBLE, vuelve a aparecer en la búsqueda si cumple las demás condiciones de RN-04 y se muestra el mensaje de éxito (EXI-CAN-03). |
| CA3 | Dado que un administrador de cancha quiere cambiar el estado de una cancha, cuando la cancha no exista, entonces no se cambia el estado y se muestra el mensaje de error (ERR-CAN-07), indicando que no existe una cancha con ese identificador. |
| CA4 | Dado que se recibe una solicitud para cambiar el estado de una cancha, cuando el usuario autenticado no sea el administrador propietario del escenario (incluido un encargado de sede), entonces no se cambia el estado y se muestra el mensaje de error (ERR-CAN-02), indicando que no tiene permiso para gestionar las canchas de este escenario. |
| CA5 | Dado que se recibe una solicitud para cambiar el estado de una cancha, cuando el estado enviado sea igual al que ya tiene la cancha, entonces no se cambia el estado y se muestra el mensaje de error (ERR-CAN-10), indicando que la cancha ya se encuentra en ese estado. |
| CA6 | Dado que un administrador de cancha quiere inactivar una cancha, cuando la cancha tenga reservas confirmadas futuras, entonces no se cambia el estado y se muestra el mensaje de error (ERR-CAN-12), indicando que hay reservas confirmadas futuras que impiden inactivarla. |
