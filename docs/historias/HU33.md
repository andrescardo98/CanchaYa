## Tarjeta

- **Como:** Administrador de cancha o encargado de sede
- **Necesito:** marcar que el jugador no se presentó a una reserva confirmada
- **Para:** llevar el registro de inasistencias que servirá de base para futuras sanciones

> Como Administrador de cancha o encargado de sede, necesito marcar que el jugador no se presentó a una reserva confirmada, para llevar el registro de inasistencias que servirá de base para futuras sanciones


## Conversación historia

- **Requisito de información:** Modelo de dominio enriquecido, hoja Reserva: atributos y responsabilidad marcarNoAsistio (políticas 14, 22, 23, 24, 32 y 33).
- **Prototipo:** Prototipo «Agenda del escenario»: Prototipos/Celular y Prototipos/Computador, archivo «17 Agenda del escenario.png» (1.1.9.5 Artefactos apoyo).
- **Catálogo de mensajes:** Catálogo de mensajes - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo), hoja «Mensajes». Códigos usados en esta HU: EXI-RES-04, CNF-RES-02, ERR-RES-14, ERR-RES-22, ERR-RES-23, ERR-RES-32.
- **Catálogo de parámetros:** Catálogo de parámetros - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo). Parámetros usados en esta HU: PAR-GEN-01 (zona horaria de la plataforma), PAR-RES-09 (plazo para marcar una inasistencia).
- **Restricciones de diseño:** Se valida en el servidor, con su propia hora, que la hora de fin de la reserva ya pasó.
- Antes de marcar la inasistencia se pide confirmación al usuario.
- La reserva queda en estado NO_ASISTIO y sirve de base para la futura política de sanciones (RN-09), que no se implementa en este alcance. La marca de inasistencia no se puede revertir y no se notifica al jugador (trabajo futuro).

## Criterios de aceptación

| Código | Escenario |
|---|---|
| CA1 | Dado que un administrador de cancha o un encargado de sede quiere registrar que un jugador no se presentó, cuando la hora de fin de la reserva ya haya pasado, ejecute la acción definida para marcar la inasistencia y acepte el mensaje de confirmación (CNF-RES-02), entonces la reserva queda en estado NO_ASISTIO y se muestra el mensaje de éxito (EXI-RES-04). |
| CA2 | Dado que un administrador de cancha o un encargado de sede quiere marcar una inasistencia, cuando la hora de fin de la reserva aún no haya pasado, entonces no se marca y se muestra el mensaje de error (ERR-RES-22), indicando que solo se puede marcar la inasistencia después de la hora de fin de la reserva. |
| CA3 | Dado que un administrador de cancha o un encargado de sede quiere marcar una inasistencia, cuando la reserva no exista o no esté CONFIRMADA, entonces no se marca y se muestra el mensaje de error (ERR-RES-14), indicando que la reserva no existe o ya no está confirmada. |
| CA4 | Dado que se recibe una solicitud para marcar una inasistencia, cuando el usuario autenticado no sea el administrador propietario ni un encargado asignado al escenario de la reserva, entonces no se marca y se muestra el mensaje de error (ERR-RES-23), indicando que no tiene permiso para marcar la inasistencia en este escenario. |
| CA5 | Dado que un administrador de cancha o un encargado de sede quiere marcar una inasistencia, cuando hayan pasado más de 24 horas desde la hora de fin de la reserva, entonces no se marca y se muestra el mensaje de error (ERR-RES-32), indicando que la inasistencia solo se puede marcar hasta 24 horas después de terminada la reserva. |
| CA6 | Dado que una reserva ya fue marcada como NO_ASISTIO, cuando el administrador de cancha o el encargado de sede la consulte en la agenda, entonces no se le ofrece ninguna opción para revertir la marca; y si se recibe una solicitud para marcarla de nuevo, no se modifica la reserva y se muestra el mensaje de error (ERR-RES-14), indicando que la reserva no está confirmada. |
