## Tarjeta

- **Como:** Administrador de cancha
- **Necesito:** asignar a un usuario como encargado de una de mis sedes
- **Para:** delegar la atención diaria sin compartir mi cuenta

> Como Administrador de cancha, necesito asignar a un usuario como encargado de una de mis sedes, para delegar la atención diaria sin compartir mi cuenta


## Conversación historia

- **Requisito de información:** Modelo de dominio enriquecido, hoja EncargadoEscenario: atributos y responsabilidad asignar (políticas 1 a 5 y 9).
- **Prototipo:** Prototipo «Encargados de sede»: Prototipos/Celular y Prototipos/Computador, archivo «20 Encargados de sede.png» (1.1.9.5 Artefactos apoyo).
- **Catálogo de mensajes:** Catálogo de mensajes - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo), hoja «Mensajes». Códigos usados en esta HU: EXI-ENC-01, ERR-ENC-01, ERR-ENC-02, ERR-ENC-03, ERR-ENC-04, ERR-GEN-01, ERR-GEN-02, ERR-ENC-09.
- **Catálogo de parámetros:** No aplican parámetros de negocio.
- **Restricciones de diseño:** Los permisos del encargado se validan en el servidor contra sus asignaciones vigentes (RN-15).
- El encargado se busca por su correo electrónico y debe tener una cuenta con rol Administrador de cancha.
- El encargado puede consultar la agenda, crear y eliminar bloqueos y marcar inasistencias del escenario; no puede modificar el escenario, sus canchas, tarifas u horarios, ni cancelar reservas (RN-15).
- El administrador propietario no puede asignarse a sí mismo como encargado de su propio escenario.

## Criterios de aceptación

| Código | Escenario |
|---|---|
| CA1 | Dado que un administrador de cancha quiere delegar la atención de una de sus sedes, cuando ingrese el correo de un usuario con rol Administrador de cancha y ejecute la acción definida para asignar, entonces se persiste la asignación con su fecha, el usuario ve el escenario en su agenda con los permisos de encargado y se muestra el mensaje de éxito (EXI-ENC-01). |
| CA2 | Dado que un administrador de cancha quiere asignar un encargado, cuando deje vacío el correo o lo ingrese sin un formato válido, entonces no se persiste la asignación y se muestran los mensajes de error respectivos (Problemas de obligatoriedad: ERR-GEN-01, Problemas de formato: ERR-GEN-02). |
| CA3 | Dado que un administrador de cancha quiere asignar un encargado, cuando el correo no corresponda a ningún usuario o el usuario no tenga rol Administrador de cancha, entonces no se persiste la asignación y se muestra el mensaje de error (ERR-ENC-03), indicando que el usuario indicado no existe o no puede ser encargado. |
| CA4 | Dado que un administrador de cancha quiere asignar un encargado, cuando el usuario ya sea encargado de ese escenario, entonces no se persiste la asignación y se muestra el mensaje de error (ERR-ENC-04), indicando que el usuario ya es encargado de este escenario. |
| CA5 | Dado que un administrador de cancha quiere asignar un encargado, cuando el escenario no exista, entonces no se persiste la asignación y se muestra el mensaje de error (ERR-ENC-01), indicando que no existe el escenario al que se quiere asignar el encargado. |
| CA6 | Dado que se recibe una solicitud para asignar un encargado, cuando el usuario autenticado no sea el administrador propietario del escenario, entonces no se persiste la asignación y se muestra el mensaje de error (ERR-ENC-02), indicando que no tiene permiso para gestionar los encargados de este escenario. |
| CA7 | Dado que un administrador de cancha quiere asignar un encargado, cuando ingrese su propio correo electrónico y ejecute la acción definida para asignar, entonces no se persiste la asignación y se muestra el mensaje de error (ERR-ENC-09), indicando que el propietario no puede ser encargado de su propio escenario. |
