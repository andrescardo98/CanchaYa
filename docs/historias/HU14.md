## Conversación historia

- **Requisito de información:** Modelo de dominio enriquecido, hoja TipoCancha: atributos y responsabilidad registrar, modificar y eliminar (política 1).
- **Prototipo:** Prototipo «Tipos de cancha»: Prototipos/Celular y Prototipos/Computador, archivo «10 Tipos de cancha.png» (1.1.9.5 Artefactos apoyo).
- **Catálogo de mensajes:** Catálogo de mensajes - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo), hoja «Mensajes». Códigos usados en esta HU: INF-TCA-01, ERR-TCA-01.
- **Catálogo de parámetros:** No aplican parámetros de negocio.
- **Restricciones de diseño:** Solo el rol ADMINISTRADOR_SISTEMA accede a la gestión del catálogo; se valida en el servidor.
- Esta es la vista de gestión del catálogo (Release 2). En el Release 1 el catálogo se carga con datos iniciales y su consulta de solo lectura queda cubierta por HU6 (registro de cancha) y HU18 (filtro por tipo de cancha).
- Desde esta lista se accede a registrar, modificar y eliminar tipos de cancha (HU15, HU16 y HU17).

## Criterios de aceptación

| Código | Escenario |
|---|---|
| CA1 | Dado que el administrador del sistema quiere revisar el catálogo de tipos de cancha, cuando ingrese a la opción de tipos de cancha, entonces se listan todos los tipos registrados con su código, nombre y capacidad de jugadores, ordenados por código. |
| CA2 | Dado que el administrador del sistema consulta el catálogo de tipos de cancha, cuando no exista ningún tipo registrado, entonces se muestra el mensaje (INF-TCA-01), indicando que aún no hay tipos de cancha registrados. |
| CA3 | Dado que se recibe una solicitud para consultar la gestión de tipos de cancha, cuando el usuario autenticado no tenga el rol Administrador del sistema, entonces no se muestra la información y se muestra el mensaje de error (ERR-TCA-01), indicando que solo el administrador del sistema puede gestionar los tipos de cancha. |
