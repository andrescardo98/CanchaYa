## Tarjeta

- **Como:** Administrador del sistema
- **Necesito:** activar los escenarios recién registrados e inactivar los que no deban mostrarse
- **Para:** que los jugadores solo encuentren escenarios revisados

> Como Administrador del sistema, necesito activar los escenarios recién registrados e inactivar los que no deban mostrarse, para que los jugadores solo encuentren escenarios revisados


## Conversación historia

- **Requisito de información:** Modelo de dominio enriquecido, hoja Escenario: atributos y responsabilidad cambiarEstado (políticas 6, 8, 9, 10, 14 y 15).
- **Prototipo:** Prototipo «Administración de escenarios»: Prototipos/Celular y Prototipos/Computador, archivo «09 Administración de escenarios.png» (1.1.9.5 Artefactos apoyo).
- **Catálogo de mensajes:** Catálogo de mensajes - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo), hoja «Mensajes». Códigos usados en esta HU: EXI-ESC-03, ERR-ESC-06, ERR-ESC-08, ERR-ESC-09, ERR-ESC-14, COR-ESC-01.
- **Catálogo de parámetros:** Catálogo de parámetros - CanchaYa.xlsx (1.1.9.5 Artefactos apoyo). Parámetros usados en esta HU: PAR-GEN-02 (reintentos de envío de correo).
- **Restricciones de diseño:** Solo el rol ADMINISTRADOR_SISTEMA accede a esta opción; se valida en el servidor. Envío de correo con un proveedor SMTP; el envío no debe bloquear ni revertir el cambio de estado.
- El administrador del sistema ve la lista de escenarios con su nombre, ciudad, administrador propietario, fecha de registro y estado, y puede filtrarla por estado para encontrar los pendientes de activación.
- No se puede inactivar un escenario con reservas confirmadas futuras en sus canchas (RN-17). Al activar o inactivar el escenario se notifica por correo al administrador propietario (RN-06).

## Criterios de aceptación

| Código | Escenario |
|---|---|
| CA1 | Dado que el administrador del sistema quiere revisar los escenarios registrados, cuando ingrese a la administración de escenarios y filtre por estado INACTIVO, entonces se listan los escenarios inactivos, incluidos los recién registrados que esperan activación. |
| CA2 | Dado que el administrador del sistema quiere publicar un escenario revisado, cuando ejecute la acción definida para activarlo, entonces el escenario queda en estado ACTIVO, sus canchas aparecen en la búsqueda si cumplen las demás condiciones de RN-04 y se muestra el mensaje de éxito (EXI-ESC-03), indicando el nuevo estado del escenario. |
| CA3 | Dado que el administrador del sistema quiere retirar un escenario de la búsqueda, cuando ejecute la acción definida para inactivarlo, entonces el escenario queda en estado INACTIVO, ni él ni sus canchas vuelven a aparecer en la búsqueda y se muestra el mensaje de éxito (EXI-ESC-03). |
| CA4 | Dado que el administrador del sistema quiere cambiar el estado de un escenario, cuando el escenario no exista, entonces no se cambia el estado y se muestra el mensaje de error (ERR-ESC-06), indicando que no existe un escenario con ese identificador. |
| CA5 | Dado que se recibe una solicitud para cambiar el estado de un escenario, cuando el usuario autenticado no tenga el rol Administrador del sistema, entonces no se cambia el estado y se muestra el mensaje de error (ERR-ESC-08), indicando que solo el administrador del sistema puede activar o inactivar escenarios. |
| CA6 | Dado que se recibe una solicitud para cambiar el estado de un escenario, cuando el estado enviado sea igual al que ya tiene el escenario, entonces no se cambia el estado y se muestra el mensaje de error (ERR-ESC-09), indicando que el escenario ya se encuentra en ese estado. |
| CA7 | Dado que el administrador del sistema quiere inactivar un escenario, cuando alguna de sus canchas tenga reservas confirmadas futuras, entonces no se cambia el estado y se muestra el mensaje de error (ERR-ESC-14), indicando que hay reservas confirmadas futuras que impiden inactivar el escenario. |
| CA8 | Dado que el administrador del sistema activa o inactiva un escenario, cuando el cambio de estado quede persistido, entonces se envía al administrador propietario un correo (COR-ESC-01) que le informa el nuevo estado de su escenario; si el envío falla, el cambio de estado no se revierte, se registra el error y no se reintenta el envío. |
